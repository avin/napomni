# Domain docs

## Before exploring

This repo uses a single-context layout.

- Read root `GLOSSARY.md` if present.
- Read relevant decisions in `docs/adr/` if present.

If these documents are absent, proceed silently.
The domain-modeling skill creates them when terminology or
decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses,
and test names.

For a missing concept, check whether existing terminology fits.
Record genuine terminology gaps for domain-modeling.

## Decisions

If a proposal contradicts an ADR, explicitly name the ADR
and explain why its decision should be reconsidered.
