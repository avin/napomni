# Итоговая проверка Windows reminders

Дата: 18 октября 2026 года. Исходная точка: `2234ae1`. Интеграционная ветка: `codex/windows-reminders`. Задача 01 была принята пользователем до начала этого прогона; задачи 02–13 реализованы и закрыты по правилам локального трекера.

## Финальная сборка и тесты

После слияния всех задач и исправлений ревью очищены только артефакты пакета `napomni` в проверенном каталоге `C:/_/napomni/target`. Это исключает повторное использование артефактов соседних рабочих копий. Зависимости не очищались.

Успешно выполнены:

- `cargo fmt --check`.
- `cargo clippy --locked --all-targets -- -D warnings`.
- `cargo test --locked`: 65 тестов прошли, 0 ошибок. Две проверки настоящих эффектов Windows намеренно ignored в обычном наборе; они выполнены отдельно в ходе реализации.
- `cargo build --locked`.

Проверяются публичные операции ядра с управляемыми временем и хранилищем, а также внешний LLM-адаптер с локальным HTTP-стендом. Настоящие платные запросы к провайдерам не выполнялись. Покрыты все виды расписаний, ограничения, DST и ручной откат часов, сон и перезапуск, снимки и общий сигнал, управление/отмена, каталог, уточнения и атомарное восстановление инструментов после ошибок.

Финальный exe запущен с `--open --test-toasts` из отдельной копии с изолированным APPDATA. Через восемь секунд процесс продолжал работу, stderr пуст. Проверочный процесс завершён. Этот запуск подтверждает работоспособность сборки, не визуальное качество.

## Настоящие эффекты Windows

- Автозапуск: явно выполнен Windows-тест HKCU Run — включение, проверка точного пути с кавычками, выключение; исходное значение восстановлено. Проверено перечисление настоящих мониторов. Геометрические тесты покрывают четыре угла и разные рабочие области при 100%, 125%, 150%. Подробности в задаче 12.
- Звук: Windows приняла запуск встроенного WAV в асинхронном цикле и остановку; проверка длилась 4,2 секунды, больше двух периодов. Это подтверждает приём вызовов API, не физическую слышимость. [Протокол звука](10-looping-sound.md).
- Стопка: настоящий popup имеет topmost/noactivate, регион исключает пустые пиксели; активное окно до и после появления не изменилось. [Протокол стопки и метаданные](11-toast-stack.md).
- Поле ввода: нативная диагностика публичных действий и IME подтвердила видимость каретки длинной строки, Home/End, выделение, обратное преобразование координат и текст с emoji/кириллицей. Диагностика выполнена в светлой теме при 100%; временный диагностический код удалён. [Протокол исправлений](review-fixes.md).

## Ревью

Две независимые проверки рассмотрели стандарты проекта и соответствие спецификации. Исправлены два P2 поля ввода и два P3 устройства ядра. Повторное ревью подтвердило устранение всех четырёх замечаний, новых доказанных дефектов не найдено. [Отчёт по двум направлениям](review.md).

## Граница непроведённой приёмки

Computer Use дважды не смог захватить настоящее GPUI-окно: `FrameArrived timed out: timed out waiting on channel`, затем `window capture timed out: timed out waiting on channel` после обновления выбора окна и активации. По непроверенным координатам ввод не выполнялся.

На целевом экране ещё требуется визуально проверить кириллицу, обе темы и масштабы 100%, 125%, 150%; анимации, наведение, прокрутку длинного текста и переполненной стопки, жест закрытия, клавиатурный вход и взаимодействие мышью с прозрачными промежутками. Физическая слышимость сигнала и запуск после настоящего нового входа в Windows также отдельно не подтверждались. Сборка, тесты, геометрия и нативные метаданные не объявляются заменой этой приёмки.

Исходный ручной сценарий жизненного цикла сохранён в [протоколе 01](01-gpui-tray-toast.md). Ограничения поиска комбинаций расписания — 400 календарных лет/100000 кандидатов; вложенные ограничения и окна через полночь явно отклоняются, без приблизительной замены. [Протокол ограничений](09-constraints.md).
