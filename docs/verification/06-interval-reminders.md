# 06: Интервальные напоминания

Сетка хранится в UTC как первая допустимая точка и положительный период в секундах. Без явного начала первая точка равна фактическому времени создания плюс период; задержка API до создания не создаёт просроченное первое срабатывание. Явное местное начало преобразуется в UTC один раз. Изменение часового пояса меняет подпись местного времени, сохраняя реальную величину интервала.

Следующая точка вычисляется арифметически за постоянное время. Закрытие карточки потребляет прошедшие повторы только своего ID; повтор при открытой карточке сохраняет её снимок, порядок и sequence. Пропуск во сне или до запуска оставляет будущую фазу сетки прежней. Тосты не сохраняются на диск. Поля длительности и автозакрытие не добавлялись.

Публичные проверки через Application:12:03→12:13→12:23, задержка до создания, неизменность открытого снимка, закрытие до следующего tick без запоздалого повторного тоста и без потери другого ID, одинаковый текст разных записей, явные будущие и прошлые привязки, нулевой/отрицательный/слишком большой период, сон, перезапуск, смена часового пояса и сохранённая исходная сетка. HTTP-стенд проверяет interval в схеме, фактический tool call и описание сохранённой сетки в результате.

cargo fmt --check, cargo clippy --locked --all-targets -- -D warnings, cargo test --locked пройдены: четыре теста интервалов и один новый HTTP-сценарий, полный набор также зелёный. Настоящий визуальный прогон интервала и звука Windows здесь не выполнен; чат и окна используют уже подключённые операции ядра задачи04.
