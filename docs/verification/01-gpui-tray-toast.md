# Проверка задачи 01 на Windows

Дата: 18 октября 2026 года. GPUI: 0.2.2, tray-icon: 0.21.3. Версии зависимостей зафиксированы в Cargo.lock.

**Итоговый статус:** задача выполнена и принята пользователем 18 октября 2026 года после исправления первого кадра тостов: «Окей, всё нормально, считаем задачу выполненной». Результаты агентского прогона ниже сохранены как история; отдельные непроведённые проверки не заявляются выполненными и не блокируют закрытие задачи по решению пользователя.

## Подтверждено в среде разработки

- Rust 1.95.0, cargo 1.95.0, Windows, цель MSVC.
- `cargo check` и `cargo build` выполнены успешно.
- `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings` и `cargo test --locked` выполнены успешно. Последняя команда запускает пустой набор: автоматизированных тестов в этой задаче нет.
- Собранное приложение запущено с `--open`. Процесс продолжил работу; stderr пуст.
- Windows вернула окно с заголовком «Напоминания» и системными кнопками сворачивания, разворачивания и закрытия. В accessibility-состоянии фокус находился в главном окне после явной активации проверяющим инструментом.

Это подтверждает сборку и создание настоящего окна, но не качество отрисовки и не сохранение фокуса при появлении тостов.

## Ограничение текущего прогона

Computer Use дважды не смог получить изображение главного окна: `FrameArrived timed out: timed out waiting on channel`, затем `window capture timed out: timed out waiting on channel`. При попытке проверить захват обычного окна механизм прекратил работу, потому что не смог надёжно определить URL браузера для применения своей политики. Дальнейшие действия через Computer Use не выполнялись.

На момент этого прогона визуальная приёмка, клики по трею и карточкам, масштабирование и проверка отсутствия перехвата фокуса оставались незавершёнными. Доказательств непригодности GPUI нет; переход на Tauri не выполнялся. Позднее пользователь принял результат и подтвердил закрытие задачи.

## Воспроизводимый приёмочный сценарий

1. Выполнить `cargo run --locked`. Убедиться, что главный экран не открывается сам, а значок колокольчика присутствует в трее, включая скрытую область значков.
2. Дважды щёлкнуть по значку. Проверить русские заголовки «Напоминания», «Список напоминаний», «Общий чат» и отсутствие обрезанного текста при минимальном размере окна.
3. Закрыть главное окно крестиком. Проверить, что процесс и значок трея остались. Двойным щелчком снова открыть окно; повторить цикл дважды. Проверить также восстановление после сворачивания.
4. Нажать «Показать тестовые тосты», переключиться в редактор и непрерывно печатать. Три карточки должны появиться сразу; ввод должен остаться в редакторе. Проверить, что карточки находятся поверх редактора и не исчезают через минуту.
5. Убедиться, что карточки находятся справа вверху основного монитора и не заходят на панель задач. Повторить с панелью задач сверху в среде, где Windows поддерживает такое размещение; вернуть исходное положение панели.
6. Проверить прямые углы окон, карточек, панелей и кнопок, отсутствие скруглений и непрозрачных областей вне карточек, клики по окружающим окнам и в промежутках между карточками. Проверить кнопку «Закрыть ×» у каждой карточки; остальные должны остаться. Повторный вызов демонстрации не должен закрывать оставшиеся карточки.
7. Повторить демонстрацию при масштабах Windows 100%, 125% и 150% в светлой и тёмной темах. Проверить кириллицу в главном окне и тостах, букву «ё», цифры, переносы строк и контраст. Чёткость оценивается на целевом экране: текст читается без заметного размытия. После проверки вернуть исходную тему и масштаб.
8. Оставить карточки открытыми, закрыть главное окно, выбрать «Выход» в меню трея. Проверить исчезновение всех карточек и значка и завершение процесса. После нового запуска карточки не должны восстанавливаться.

## Исправление первого кадра тоста

Пользователь предоставил снимки: после появления карточки обрезаны справа, кнопка закрытия не видна, текст не переносится; клик исправляет изображение.

Воспроизведено на настоящих окнах Windows без кликов. Временная диагностика сравнивала `Window::viewport_size()` во время отрисовки с `GetClientRect`, приведённым к логическим пикселям. Запуск отдельной диагностической сборки с `--test-toasts`, ожидание 8 секунд и проверка журнала завершились ошибкой: GPUI использовал область 2564×1029 при реальной клиентской области 352×148. Несоответствие повторилось на всех трёх тостах.

Причина: `SetWindowPos` вызывался внутри `WindowHandle::update`. Синхронное сообщение `WM_SIZE` пыталось повторно войти в обновление GPUI и не могло обновить размер раскладки. Перенос размещения и показа в отдельную задачу основного потока позволяет обработать уведомление о размере. После изменения та же проверка прошла: раскладка 352×148 совпала с клиентской областью 352×148 во всех кадрах показанных карточек без кликов. Флаги запрета активации и квадратный стиль сохранены.

Временная диагностика удалена. Постоянный автоматизированный тест не добавлялся: в проекте пока нет отдельного стенда настоящего GPUI-рендеринга, а тест внутренней структуры элементов не проверил бы этот дефект. Для регрессии: запустить `cargo run --locked -- --test-toasts`, не касаться карточек мышью и сразу проверить правую границу, кнопку «Закрыть ×» и переносы текста у всех трёх тостов. Измерение раскладки не заменяет общую визуальную приёмку темы, DPI и чёткости текста.

## Исправление обрезанной правой рамки — 19 октября 2026 года

Отдельная правая полоса внутри карточки не исправила дефект и удалена. В настоящем диагностическом запуске `--test-toasts` ширина карточки составляла 368 px, а `Window::viewport_size()` и `GetClientRect` возвращали 352 px. GPUI сохраняет неклиентские отступы даже у popup без заголовка: на проверенном мониторе по 8 px слева и справа и 8 px снизу. Прямой `SetWindowPos` задавал внешнюю ширину 368 px, поэтому последние 16 px карточки, включая правую рамку, выходили за клиентскую область. Предыдущее совпадение viewport с клиентской областью 352 px не проверяло соответствие ширине карточки.

`place_toast` теперь сначала перемещает окно на нужный монитор для обновления DPI, затем измеряет отступы и задаёт внешние границы так, чтобы клиентская область совпала с `Placement::viewport`. `toast_region` переводит прямоугольники карточек из клиентских координат в оконные координаты `SetWindowRgn`.

Повтор того же запуска с отдельным APPDATA: карточка, viewport и клиентская область имеют ширину 368 px; внешняя ширина окна — 384 px. `GetWindowRgn` возвращает горизонтальные границы 8–376 px, совпадающие с клиентской областью внутри HWND. Сравнение диагностических журналов: до исправления `FAIL card=368 client=352`, после — `PASS card=368 client=368`. Временные журналы и вызовы диагностики удалены из кода. Проверка подтверждает устранение измеренного обрезания на текущем мониторе; визуальная приёмка других DPI остаётся отдельной проверкой.
