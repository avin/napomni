# Разработка Napomni

Пользовательские инструкции находятся в [README.md](README.md). Здесь описаны устройство проекта, запуск из исходников, отладка, проверки и сборка.

## Окружение

Разработка и проверка приложения рассчитаны на Windows 10/11 x64. Нужны:

- Rust с поддержкой edition 2024 и целью `x86_64-pc-windows-msvc`;
- Visual Studio Build Tools с компонентами разработки на C++, компоновщиком MSVC и Windows SDK;
- графический адаптер с поддержкой DirectX для GPUI.

Команды ниже выполняются в PowerShell из корня репозитория. Зависимости зафиксированы в `Cargo.lock`; используйте `--locked`, чтобы сборка не меняла их версии. Отдельного веб-интерфейса и сборки через Node.js нет.

## Запуск и сборка

Запустить приложение и сразу открыть главное окно:

```powershell
cargo run --locked -- --open
```

Без `--open` программа запускается в трее. Закрытие главного окна скрывает его; завершение выполняется через «Выход» в меню трея.

Показать демонстрационную стопку из трёх беззвучных карточек:

```powershell
cargo run --locked -- --open --test-toasts
```

Карточки появляются сразу и не создают сохранённых напоминаний. Та же демонстрация доступна по кнопке «Тест тостов» в настройках.

Собрать исполняемый файл для использования вне Cargo:

```powershell
cargo build --release --locked
.\target\release\napomni.exe
```

При стандартном каталоге Cargo результат находится в `target/release/napomni.exe`, отладочная сборка — в `target/debug/napomni.exe`.

Для автозапуска используется путь текущего исполняемого файла. Включайте его из постоянной копии приложения: запуск через Cargo привяжет автозапуск к артефакту сборки.

## Релизы через GitHub Actions

Workflow [Release](.github/workflows/release.yml) запускается при отправке тега вида `v1.2.3` в GitHub:

```powershell
git tag v0.1.0
git push origin v0.1.0
```

Перед созданием тега закоммитьте изменения и отправьте их вместе с workflow в GitHub. Для следующего релиза используйте новый номер версии.

GitHub запускает тесты и собирает приложение на Windows для `x86_64-pc-windows-msvc`. Версия в `Cargo.toml` и запись приложения в `Cargo.lock` получают номер из тега только на время сборки; коммит в репозитории не меняется.

После успешной сборки workflow создаёт установщик через Inno Setup 6, публикует GitHub Release с автоматически составленным списком изменений и помечает его как Latest. Единственный прикреплённый файл — `Napomni-<версия>-windows-x64-setup.exe`. Для публикации используется встроенный `GITHUB_TOKEN`; дополнительные секреты не нужны.

Установщик размещает приложение и `README.md` в `%LOCALAPPDATA%\Programs\Napomni` без запроса прав администратора, создаёт ярлык в меню «Пуск» и по выбору — на рабочем столе. Удаление доступно через список установленных приложений Windows. Повторный запуск установщика обновляет ту же установку; пользовательские данные в `%APPDATA%` сохраняются.

Сценарий установщика находится в [installer/napomni.iss](installer/napomni.iss). Для локальной сборки установите Inno Setup 6 и выполните:

```powershell
cargo build --release --locked --target x86_64-pc-windows-msvc
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" /DAppVersion=0.1.0 installer/napomni.iss
```

Результат появится в `dist/`. Inno Setup 6 уже установлен на GitHub runner `windows-2022`.

## Устройство проекта

Приложение написано на Rust. Интерфейс использует GPUI Kit, зафиксированный на версии `0.7.3`; текст в Windows выводится через DirectWrite. Причины выбора описаны в [ADR 0002](docs/adr/0002-gpui-directwrite.md), термины — в [GLOSSARY.md](GLOSSARY.md).

| Файлы | Ответственность |
| --- | --- |
| `src/main.rs` | Запуск GPUI, трей, жизненный цикл окон, опрос состояния каждые 40 мс |
| `src/ui.rs`, `src/model_picker.rs` | Главное окно, чат, список напоминаний, подключение и выбор модели |
| `src/reminder_ui.rs` | Связь ядра с интерфейсом, показом карточек и звуком |
| `src/reminders.rs`, `src/mutations.rs` | Состояние, планировщик, сохранение, изменение записей и отмена |
| `src/calendar.rs`, `src/interval.rs`, `src/weekly.rs`, `src/calendar_dates.rs`, `src/constraints.rs` | Расчёт расписаний и их ограничений |
| `src/chat.rs`, `src/catalog.rs` | Настройки подключения, история, HTTP-запросы и каталог моделей |
| `src/reminder_tools.rs`, `src/mutation_tools.rs`, `src/commands.rs` | Инструменты модели, выполнение команд и восстановление ответа |
| `src/toast_stack.rs` | Окно стопки, анимации, прокрутка и закрытие карточек |
| `src/placement.rs`, `src/settings_ui.rs`, `src/native.rs` | Размещение, настройки, мониторы, DPI, автозапуск и Windows API |
| `src/sound.rs` | Встроенный повторяющийся сигнал через Windows PlaySound |
| `tests/` | Интеграционные проверки ядра и HTTP-адаптера |

Библиотечное ядро экспортируется через `src/lib.rs`. Интерфейсные модули подключены отдельно в бинарном пакете. Для асинхронных запросов используются Tokio, reqwest и async-openai; сетевые операции выполняются в фоне.

## Контракты, которые важно сохранять

- Сохранённое расписание исполняет локальное ядро. Модель интерпретирует команды через инструменты; текстовый ответ сам по себе данные не меняет.
- `Application` получает `Clock` и `ReminderStore`. В тестах это позволяет управлять временем и хранилищем без ожидания настоящего срабатывания.
- Календарные расписания следуют местному времени Windows, интервальные сохраняют исходную сетку. После сна и перезапуска пропущенные срабатывания не догоняются.
- `ToastSnapshot` фиксирует текст, рамку и звук на момент показа. Изменение, пауза или удаление записи не меняют открытый снимок. На одно напоминание открыт максимум один тост.
- Общий звуковой сигнал работает, пока открыт хотя бы один звучащий снимок. Закрытие карточки должно обновлять состояние сигнала через общий путь.
- `execute_tool_once` сохраняет изменение и квитанцию выполнения одной транзакцией. Повтор того же вызова в рамках команды возвращает сохранённый результат; другие аргументы с тем же ID отклоняются. Продолжение ответа восстанавливает контекст из квитанций.
- Поиск расписания с ограничениями ограничен 400 календарными годами и 100 000 кандидатами. Вложенные ограничения и окна через полночь отклоняются; приблизительная замена правила не допускается.

## Подключение модели

Провайдер должен поддерживать OpenAI-совместимые Chat Completions и tool calling. Базовый URL, ключ и ID модели задаются через интерфейс. «Проверить» выполняет реальный запрос с безопасным инструментом `connection_probe`, который не меняет напоминания.

Каталог загружается отдельно; при его недоступности доступен ручной ввод ID. Для OpenRouter учитываются метаданные поддержки инструментов. Неизвестные возможности модели проверяются запросом.

Автоматические HTTP-тесты используют локальный сервер. Для обычного набора тестов ключ провайдера и платные запросы не нужны.

## Локальные данные

Пути относительно `%APPDATA%`:

| Файл | Содержимое |
| --- | --- |
| `napomni/connection.json` | Адрес провайдера, API-ключ и модель |
| `napomni/chat.json` | История чата и результаты операций |
| `napomni/reminders.json` | Напоминания, последнее отменяемое изменение и квитанции инструментов |
| `napomni/pending-command.json` | Контекст незавершённого ответа для продолжения |
| `napomni/placement.json` | Монитор, угол экрана и настройка автозапуска |

При записи напоминаний и контекста продолжения сначала создаётся файл `.pending`, затем он заменяет основной файл. Открытые тосты существуют только в памяти.

API-ключ хранится в `connection.json` открытым текстом. Сохранение истории и контекста продолжения маскирует известные ключи. При передаче диагностических данных проверяйте файлы на секреты и личную переписку.

Автозапуск записывает значение `napomni` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Подмена `APPDATA` изолирует файлы, но не этот ключ реестра.

## Отладка

Для воспроизведения проблемы на чистых данных запустите уже собранное приложение с отдельным `APPDATA`. Пример создаёт уникальный временный каталог и восстанавливает переменную после завершения процесса:

```powershell
cargo build --locked
$savedAppData = $env:APPDATA
$debugAppData = Join-Path ([System.IO.Path]::GetTempPath()) ('napomni-debug-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $debugAppData | Out-Null
try {
    $env:APPDATA = $debugAppData
    Start-Process -FilePath '.\target\debug\napomni.exe' -ArgumentList '--open', '--test-toasts' -Wait -WindowStyle Hidden
}
finally {
    $env:APPDATA = $savedAppData
}
```

Закончите сеанс через «Выход» в трее. Тестовые данные останутся в `$debugAppData` для изучения. Во время такого запуска не включайте автозапуск: он использует общий пользовательский реестр.

В `Cargo.toml` у профилей `dev` и `test` задано `debug = 0`. Для пошаговой отладки соберите приложение с отладочными символами:

```powershell
cargo --config 'profile.dev.debug=2' build --locked
```

Откройте `target/debug/napomni.exe` в отладчике с поддержкой Rust/MSVC либо подключитесь к процессу. Для разбора паники задайте `$env:RUST_BACKTRACE = '1'` перед запуском. Приложение собрано как Windows GUI и не открывает консоль; ошибки части нативных операций пишутся в stderr, постоянного файлового журнала нет. Ошибки подключения и команд также выводятся в интерфейсе. На наличие видимого вывода в терминале полагаться не следует.

Начальные точки для поиска: `Application::tick` при проблемах со временем, `execute_tool_once` при повторных изменениях, `reminder_ui::poll` при рассогласовании ядра, карточек и звука.

## Проверки перед передачей изменений

```powershell
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --locked
```

Для точечной проверки запускайте соответствующий интеграционный набор, например:

```powershell
cargo test --locked --test command_replay
cargo test --locked --test constraints
```

Проверки реальных эффектов Windows по умолчанию пропущены. Запускайте их отдельно, когда нужно проверить соответствующую часть:

```powershell
cargo test --locked --test sound_windows -- --ignored
cargo test --locked --bin napomni windows_autostart_roundtrip -- --ignored
```

Первая проверка включает встроенный сигнал примерно на 4,2 секунды. Вторая временно меняет пользовательский ключ автозапуска и восстанавливает прежнее значение.

Для изменений интерфейса вручную проверьте кириллицу, светлую и тёмную темы, масштабы 100%, 125% и 150%, длинный текст, переполненную стопку, наведение, закрытие жестом и отсутствие захвата фокуса при появлении карточек. При изменении размещения проверьте несколько мониторов и панель задач; при изменении звука проверьте фактическую слышимость и остановку после закрытия последней звучащей карточки.

Протоколы прошлых проверок находятся в [docs/verification](docs/verification/windows-reminders.md). Они фиксируют результаты конкретных прогонов. В них отмечены и границы приёмки: успешная сборка или ответ Windows API не подтверждают визуальное качество и слышимость. Некоторые описания интерфейса в старых протоколах расходятся с текущим кодом: например, меню трея сейчас содержит только открытие главного окна и выход.

## Ресурсы и решения проекта

`build.rs` встраивает иконку из `assets/app.rc` и задаёт для MSVC резерв стека исполняемого файла 8 МиБ. Изображение колокольчика и звуковой сигнал входят в сборку. Исходники ресурсов и команда пересоздания ICO описаны в [assets/README.md](assets/README.md).

Перед изменением доменных правил сверяйтесь с [GLOSSARY.md](GLOSSARY.md) и [ADR](docs/adr/). Правила работы с локальными задачами описаны в [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).
