# 04: Полное управление напоминаниями через CLI

**What to build:** Внешний агент управляет тем же списком напоминаний и с теми же возможностями, что внутренний чат: создаёт, изменяет, приостанавливает, возобновляет, удаляет и отменяет последнее изменение. Пользователь видит фактический результат в обычном интерфейсе, а расписания продолжают исполняться локально.

**Blocked by:** 02 — CLI: общий список и фоновый запуск приложения.

**Status:** ready-for-agent

- [ ] CLI предоставляет создание, частичное изменение, паузу, возобновление, удаление и отмену последнего изменения в дополнение к общему списку из задачи 02.
- [ ] Поддерживаются все текущие однократные, интервальные, недельные, месячные и годовые расписания, интервал после закрытия и существующие ограничения. Правила времени и проверки аргументов совпадают с внутренним чатом.
- [ ] Все операции используют общее ядро и существующие прикладные правила; для них не вызывается внутренняя модель и не требуется подключённый провайдер.
- [ ] Напоминание, созданное через чат, доступно внешнему списку и изменению по его стабильному идентификатору. Напоминание из CLI видно в интерфейсе и доступно внутреннему чату.
- [ ] Результаты списка и команд содержат фактические данные, необходимые вызывающей стороне для выбора записи и проверки изменения. Совпадающий текст не используется как уникальный идентификатор разных напоминаний.
- [ ] Частичное изменение сохраняет все неуказанные свойства и не затрагивает другие записи. Неверные аргументы и неизвестный идентификатор возвращают ошибку без изменения данных и последней отменяемой операции.
- [ ] Отмена остаётся общей для приложения и действует по существующим правилам для создания, изменения, переключения паузы и удаления независимо от источника операции.
- [ ] Изменение, пауза, удаление и отмена не меняют содержимое уже открытых тостов. Пауза и удаление сохраняют текущие правила отмены отложений; возобновление не переигрывает пропущенные срабатывания.
- [ ] Успех изменяющей команды возвращается после сохранения фактического изменения. Ошибки сохранения не выдают ложного успеха и не повреждают существующие данные. Успешные изменения доступны после перезапуска.
- [ ] Существующее восстановление операций внутреннего чата и его квитанции сохраняют поведение; эта задача не меняет правила повторных внешних разовых уведомлений.
- [ ] Интеграционные проверки проходят через общий обработчик и публичное ядро с управляемым временем, временным хранилищем и отказами сохранения. Они охватывают работу с записью из чата, все операции, общую отмену, снимки открытых карточек и сохранение остальных свойств.
- [ ] Настоящий CLI демонстрирует создание, получение результата из общего списка, изменение и удаление записи. Справка описывает реализованные команды и поддерживаемые формы расписаний.
