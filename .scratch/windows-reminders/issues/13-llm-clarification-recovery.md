# 13: Уточнения и восстановление после ошибок LLM

**What to build:** Пользователь получает предсказуемый результат при неоднозначных командах, некорректных инструментах и сбоях API: чат уточняет намерение или сообщает фактическое состояние, а данные не меняются произвольно и операции не повторяются из-за ошибки итогового ответа.

**Blocked by:** 05 — Редактирование, пауза, удаление и отмена.

**Status:** claimed

- [ ] Неоднозначная команда вызывает уточнение без предварительного изменения данных; последующий ответ продолжает нужный диалог с сохранением явно выбранной записи.
- [ ] Неподдерживаемое расписание объясняется пользователю и не заменяется приблизительным; обычный текст о выполнении не считается операцией.
- [ ] Неверные аргументы, неизвестный ID и несовместимая модель не меняют данные; ошибка доступна в русском интерфейсе.
- [ ] Успешное выполнение инструмента возвращает модели фактический результат, который учитывается приложением независимо от получения итогового текста.
- [ ] Сбой API после успешного создания или изменения не приводит к повторной операции и не показывается как доказательство, что изменения не было; интерфейс отражает фактический результат.
- [ ] Повторная отправка или восстановление обработки одного уже выполненного вызова не создаёт дубль записи и не выполняет повторное удаление или изменение состояния.
- [ ] Проверены задержанный ответ для относительного времени и даты «завтра», устаревшее целевое время, одинаковый текст разных записей и сохранение остальных свойств при исправлении команды.
- [ ] Сетевое ожидание, ошибка и восстановление чата не останавливают локальное исполнение сохранённых расписаний.
- [ ] Локальный HTTP-стенд и прикладные операции с управляемым временем воспроизводят сбои до инструмента и после него; тесты проверяют данные и видимый результат, а не точную формулировку настоящей модели.
