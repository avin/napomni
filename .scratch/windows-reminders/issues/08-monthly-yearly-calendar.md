# 08: Ежемесячные и ежегодные напоминания

**What to build:** Пользователь задаёт числа месяца и ежегодные даты через чат и получает тосты в допустимые календарные даты без автоматического переноса несуществующих дат.

**Blocked by:** 04 — Первое напоминание: от команды до тоста.

**Status:** resolved

- [x] Через чат создаются ежемесячные напоминания по выбранным числам и ежегодные напоминания по дате и времени.
- [x] Расписание сохраняется, отображается в списке и понятно пересказывается в результате чата.
- [x] Правило на 31-е пропускает месяцы без 31-го, не переносится на последний день и продолжает работать в следующем подходящем месяце.
- [x] Ежегодное 29 февраля срабатывает только в високосный год; невозможные конкретные даты не сохраняются как другое число.
- [x] Правила следуют местному времени Windows и общим ограничениям: повторившееся местное время не даёт второй показ, отсутствующее время пропускается.
- [x] Перезапуск сохраняет расписание, но не восстанавливает тосты и не догоняет пропущенные даты.
- [x] Открытый тост записи исключает создание дубля при следующем срабатывании.
- [x] Прикладные проверки с управляемым временем покрывают короткие месяцы, переход года, високосный и невисокосный годы, пропуски и сохранение записи. Есть воспроизводимый сценарий от команды до тоста.

## Answer

Реализованы monthly по выбранным числам и yearly по парам месяц/день, несколько времён, сохранение, описания и инструменты чата. Короткие месяцы и невисокосные годы пропускаются без переноса. Общая политика календаря задачи07 обеспечивает местное время, пропуск DST gap, первый момент fold и устойчивый курсор, в том числе при открытом тосте.

Пять прикладных тестов и HTTP-сценарий прошли вместе с полным набором, fmt и clippy. Подробности — [протокол](../../../docs/verification/08-monthly-yearly.md). Настоящая визуальная проверка новых календарных сценариев пока не выполнена.
